# Ztime 产品开发文档

版本 0.2.3 · Windows / Android · 2026-10-31

## 用户与任务

Ztime 是一份个人应用时间账本。目标用户在 Windows 电脑与 Android 手机之间切换，希望在周中回答三个问题：两台设备各用了多久，哪些应用占用时间最多，与上周同一时刻相比发生了什么变化。用户可保留原始时段，自己选择与哪台设备同步，也可以导出后独立分析。

典型流程是先在电脑启动 Ztime，在手机授权使用情况访问，再扫码配对并在电脑确认。手机下一次同步成功后，用户可以在“今日”按设备查看排行，在“每周”比较变化，从应用详情核对记录。两端离线时仍可分别记录。看对端数据前应先核对上次同步时间。

## 0.2.3 的功能与验收口径

- **采集。** Windows 持续记录前台应用，阅读时即使没有键鼠输入也计时；切换、锁屏、休眠、暂停或退出会结束相应时段。关窗后托盘继续运行。Android 仅将亮屏且解锁的前台应用计入，首次授权尝试读取最近两天的可用系统事件。熄屏听播客不计入。
- **日与周。** 默认使用香港时区、04:00 换日、周一开周。例：03:50–04:10 的 20 分钟在两天各计 10 分钟。周三中午查看本周变化，比较窗口应止于上周三对应时刻。修改日界线或时区后按原始时间戳重新聚合。
- **同时使用。** 电脑使用 30 分钟，其中 10 分钟同时使用手机，结果应显示电脑 30 分钟、手机 10 分钟、设备累计 40 分钟。任何产品文案、图表和导出说明均应把设备累计与个人注意力区分开。
- **仪表盘。** 今日、每周分别保存布局。电脑可拖动、缩放或隐藏模块，手机使用独立单列布局。隐藏顶部卡后仍须能进入编辑并恢复模块。主题、颜色和布局在本机持久保存。
- **账本管理。** 支持暂停、恢复、按应用查看记录、删除和 JSON / CSV 导出。解除配对停止后续同步，已接收时段留在本机。删除操作生成标记，在再次同步后传播，旧数据重放不得让该记录重新出现。

## 数据从哪里来，怎样成为报表

1. **生成区间。** Windows 采集脚本约每 1.5 秒读取前台进程，采集器将连续样本写成区间。超过约 10 秒的未知间隙不会补时。Android 使用系统事件重建前台、屏幕及锁定状态，通过设备、包名和开始时刻生成稳定记录标识，便于延长同一时段。[Windows 采集器](../desktop/collector.js) · [Android 事件处理](../android/app/src/main/java/org/timeledger/app/UsageCollector.java)
2. **落入本机账本。** SQLite 保存设备、时段和同步状态。时段包含记录 ID、来源设备、应用标识及名称、起止时间、变更序号和删除标记。电脑端使用 WAL；本地储存未额外加密。导出含设备标识，公开复现问题应使用合成数据。[Windows 存储](../desktop/store.js) · [Android 存储](../android/app/src/main/java/org/timeledger/app/LedgerDb.java)
3. **与已配对设备交换。** 电脑展示配对信息并确认请求，手机核对 TLS 证书指纹；后续请求使用令牌。同步按游标和变更序号推进，接收端校验来源并处理重放。统计设置可以同步，布局按设备保存。默认 TCP 40327 承载 TLS，UDP 40328 用于发现。本地界面 HTTP 仅监听回环地址。[电脑同步协议](../desktop/protocol.js) · [手机同步客户端](../android/app/src/main/java/org/timeledger/app/SyncClient.java)
4. **聚合与展示。** 统计层按时区计算日、周边界，将时段裁剪到查询区间，再按设备、应用及时段汇总。Windows 页面通过本机 API 获取数据，Android 通过 WebView 原生桥访问本机数据。两端共用布局和图表代码。[日期聚合](../shared/time.js) · [本机 API](../desktop/server.js) · [仪表盘](../web/dashboard.js)

## 构建、数据保护与回归

从源码仓库运行需 Node.js 24+、pnpm，桌面框架为 Electron。Windows 便携程序把账本放在程序旁的 `data` 目录，源码运行默认使用项目下的 `.data`。复现和测试必须选择隔离目录。以下命令从项目根目录执行，使用新的临时路径。

```powershell
pnpm install --frozen-lockfile
$env:TIME_LEDGER_DATA_DIR = Join-Path ([IO.Path]::GetTempPath()) ("ztime-dev-" + [guid]::NewGuid())
node --test tests/*.test.js
pnpm start
```

Android 使用 JDK 17、SDK 35、Gradle 8.13，最低 API 28。共享页面在构建时复制到 APK。Windows 打包入口、Android 构建命令及 Playwright 配置见仓库说明。[开发与构建](../README.md)

更新已有便携程序前先停止写入并备份完整数据目录，保留原路径、数据库及配对身份。发行包使用干净源码或经过排除检查的归档；调试签名密钥由维护者单独保存。GitHub 提供的是源码，Android 自行构建使用新签名时不能覆盖不同签名的现有安装。

**本版验证记录。** 2026-10-31 首次公开源码时重新运行核心测试，19 项通过。以往的浏览器交互、便携包与 Android 构建结果按版本记录。仍待现场确认的事项有 Windows 重启后的自启、真实局域网配对、Android 锁屏切换与后台省电行为。配对超时应先确认当前网络地址和电脑是否收到请求，再检查对应程序及端口的入站规则；本机连通不足以证明手机可达。[核心测试](../tests/core.test.js) · [仪表盘测试](../tests/dashboard.test.js) · [历史验证记录](validation.md)

## 待决定的开发方向

**行为分类提案。** 使用场景是把桌面课程网页和手机词典一起归入“学习”，周末能说明每段时间为何被计入。建议分两次验收，均需另行确认后进入开发。

1. **先用已有应用记录验证价值。** 用户定义“学习”等行为，将应用与行为关联，查看今日、每周和未分类时长，可对单段作手动修正。建议优先级为手动修正、用户排序的首条匹配规则、未分类。保留原始时段，以独立分类结果支持回算。验收样例：词典 10 分钟中有 2 分钟所在的独立记录被手动改为“工作”，重算后应保留学习 8 分钟、工作 2 分钟，总计仍为 10 分钟。
2. **再验证前台网页细分。** 电脑端扩展需单独授权，仅匹配正在使用的浏览器窗口和标签页。浏览器 30 分钟中若有 20 分钟命中课程页面，课程占 20 分钟，浏览器总量仍为 30 分钟。扩展断开时保留应用记录，历史未采集网址的区间无法回填网页分类。手机端第一阶段只按应用归类。

动工前应确定域名、子域名及路径的匹配方式，哪些最小字段允许保存或同步，双端离线改同一规则如何解决冲突，以及回算如何保留手动修正。验收时应覆盖多规则命中、跨日、断线重试和旧客户端配对。以上均为提案。

**iOS 可行性。** 如果目标是让 iPhone 用户看本机报告，可评估 Apple 的个人授权与报告扩展。如果目标是将 iPhone 使用明细同步进现有 Windows 账本，需另验发行地区、数据授权与返回粒度；汇总时间桶不能直接伪造成应用起止记录。目前项目包含 Windows 与 Android 两个客户端。[Screen Time 对照调研及 Apple 官方依据](SCREEN-TIME.md)
