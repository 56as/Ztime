# Ztime 产品开发文档

版本 0.2.3 · Windows / Android · 2026-10-31

## 后续功能的开发顺序

每个新增功能先给项目负责人可打开的[设计评审入口](../design/review/使用说明.md)，并在聊天中附上直达该功能和相应设备状态的链接。提交设计稿后停在评审阶段。负责人可直接试改文字、字号，或用编号批注位置和交互，再按意见改稿并回传同一入口。收到负责人明确确认后进入正式实现，设计稿与功能代码分别提交 Git。

1. 市场调研。确认目标用户的任务、现有替代办法和仍未解决的问题，分别记录事实与待验证的假设。
2. 产品需求。写清用户流程、范围和可观察的验收条件。
3. **UI 设计稿与 UX 交互原型。** UI 评审覆盖桌面和手机的排版、字号、颜色、间距与控件状态。UX 评审要求用户从入口实际点击到结果，检查成功、等待、失败、取消和重试时能否理解下一步。评审者选点，按编号记录位置、操作路径、意见和期望。设计者先改稿，评审者在同一处复核后关闭批注。涉及布局或流程的新需求回到此步骤评审。
4. 软件架构。依据确认过的设计和交互，确定所需数据、接口、同步及兼容方式。
5. 实现与验收。将确认的设计应用到产品，用隔离数据逐页对照画板和验收条件，检验真实流程。

## 用户与任务

Ztime 是一份个人应用时间账本。目标用户在 Windows 电脑与 Android 手机之间切换，希望在周中回答三个问题：两台设备各用了多久，哪些应用占用时间最多，与上周同一时刻相比发生了什么变化。用户可保留原始时段，自己选择与哪台设备同步，也可以导出后独立分析。

典型流程是先在电脑启动 Ztime，在手机授权使用情况访问，再扫码配对并在电脑确认。手机下一次同步成功后，用户可以在“今日”按设备查看排行，在“每周”比较变化，从应用详情核对记录。两端离线时仍可分别记录。看对端数据前应先核对上次同步时间。

## 0.2.3 的功能与验收口径

- **采集。** Windows 持续记录前台应用，阅读时即使没有键鼠输入也计时；切换、锁屏、休眠、暂停或退出会结束相应时段。关窗后托盘继续运行。Android 仅将亮屏且解锁的前台应用计入，首次授权尝试读取最近两天的可用系统事件。熄屏听播客不计入。
- **日与周。** 默认使用香港时区、04:00 换日、周一开周。例：03:50–04:10 的 20 分钟在两天各计 10 分钟。周三中午查看本周变化，比较窗口应止于上周三对应时刻。修改日界线或时区后按原始时间戳重新聚合。
- **同时使用。** 电脑使用 30 分钟，其中 10 分钟同时使用手机，结果应显示电脑 30 分钟、手机 10 分钟、设备累计 40 分钟。任何产品文案、图表和导出说明均应把设备累计与个人注意力区分开。
- **仪表盘。** 今日、每周分别保存布局。电脑可拖动、缩放或隐藏模块，手机使用独立单列布局。隐藏顶部卡后仍须能进入编辑并恢复模块。主题、颜色和布局在本机持久保存。
- **账本管理。** 支持暂停、恢复、按应用查看记录、删除和 JSON / CSV 导出。解除配对停止后续同步，已接收时段留在本机。删除操作生成标记，在再次同步后传播，旧数据重放不得让该记录重新出现。

## 数据从哪里来，怎样成为报表

1. **生成区间。** Windows 采集脚本约每 1.5 秒读取前台进程，采集器将连续样本写成区间。超过约 10 秒的未知间隙不会补时。Android 使用系统事件重建前台、屏幕及锁定状态，通过设备、包名和开始时刻生成稳定记录标识，便于延长同一时段。[Windows 采集器](../desktop/collector.js) · [Android 事件处理](../android/app/src/main/java/org/timeledger/app/UsageCollector.java)
2. **落入本机账本。** SQLite 保存设备、时段和同步状态。时段包含记录 ID、来源设备、应用标识及名称、起止时间、变更序号和删除标记。电脑端使用 WAL；本地储存未额外加密。导出含设备标识，公开复现问题应使用合成数据。[Windows 存储](../desktop/store.js) · [Android 存储](../android/app/src/main/java/org/timeledger/app/LedgerDb.java)
3. **与已配对设备交换。** 电脑展示配对信息并确认请求，手机核对 TLS 证书指纹；后续请求使用令牌。同步按游标和变更序号推进，接收端校验来源并处理重放。统计设置可以同步，布局按设备保存。默认 TCP 40327 承载 TLS，UDP 40328 用于发现。本地界面 HTTP 仅监听回环地址。[电脑同步协议](../desktop/protocol.js) · [手机同步客户端](../android/app/src/main/java/org/timeledger/app/SyncClient.java)
4. **聚合与展示。** 统计层按时区计算日、周边界，将时段裁剪到查询区间，再按设备、应用及时段汇总。Windows 页面通过本机 API 获取数据，Android 通过 WebView 原生桥访问本机数据。两端共用布局和图表代码。[日期聚合](../shared/time.js) · [本机 API](../desktop/server.js) · [仪表盘](../web/dashboard.js)

## 构建、数据保护与回归

从源码仓库运行需 Node.js 24+、pnpm，桌面框架为 Electron。Windows 便携程序把账本放在程序旁的 `data` 目录，源码运行默认使用项目下的 `.data`。复现和测试必须选择隔离目录。以下命令从项目根目录执行，使用新的临时路径。

```powershell
pnpm install --frozen-lockfile
$env:TIME_LEDGER_DATA_DIR = Join-Path ([IO.Path]::GetTempPath()) ("ztime-dev-" + [guid]::NewGuid())
node --test tests/*.test.js
pnpm start
```

Android 使用 JDK 17、SDK 35、Gradle 8.13，最低 API 28。共享页面在构建时复制到 APK。Windows 打包入口、Android 构建命令及 Playwright 配置见仓库说明。[开发与构建](../README.md)

更新已有便携程序前先停止写入并备份完整数据目录，保留原路径、数据库及配对身份。发行包使用干净源码或经过排除检查的归档；调试签名密钥由维护者单独保存。GitHub 提供的是源码，Android 自行构建使用新签名时不能覆盖不同签名的现有安装。

**本版验证记录。** 2026-10-31 首次公开源码时重新运行核心测试，19 项通过。以往的浏览器交互、便携包与 Android 构建结果按版本记录。仍待现场确认的事项有 Windows 重启后的自启、真实局域网配对、Android 锁屏切换与后台省电行为。配对超时应先确认当前网络地址和电脑是否收到请求，再检查对应程序及端口的入站规则；本机连通不足以证明手机可达。[核心测试](../tests/core.test.js) · [仪表盘测试](../tests/dashboard.test.js) · [历史验证记录](validation.md)

## 已确认的体验目标：已配对设备在局域网内一键双向同步

第一次在手机扫码、电脑确认后保存配对关系。以后只要两端处于可互访的局域网且能响应，用户在任意一端点击一次「立即同步」即可。另一端无需点按钮、再次扫码或填写 IP。同一路由器下，电脑接网线、手机连 Wi-Fi 也应适用。

一次同步先让两端各自更新已授权的本地使用记录，再交换上次同步之后的变化（含删除标记）。两端都确认接收后显示完成及最近成功时间。重复点击或失败重试不得重复计时。没有新数据时显示「已是最新」。暂时不可达时保留配对、账本与上次成功时间，用户可在网络恢复后直接重试。

**验收用例。** 两端离线期间各新增一段记录。回到可互访的局域网，仅点电脑端按钮，核对双方均得到两段记录；换一组新增记录，仅点手机端，结果相同。再点一次，总时长保持一致。更换局域网地址后仍须识别原配对设备。手机被系统暂停、电脑休眠或访客网络隔离时，应显示等待或未连接，不能报同步成功。

**0.2.3 的实现差距。** 手机按钮已触发本地采集和增量上传、下载；电脑按钮目前只提示等待手机连接。电脑发起后如何触达前台或后台的已配对手机，留到原型评审后的架构阶段验证。此处描述的双入口体验尚未发布。

### 0.2.4 本地候选版的实现与验收

电脑发起时为每台已配对手机登记一个有效期 45 秒的请求。手机在前台通过既有、校验证书指纹的 HTTPS 连接等待请求，收到后采集并交换增量。后台任务被系统调度时也可领取请求。手机收到最后一批数据、写入本地并确认后，电脑才显示该设备已完成。无更新、超时、未配对和部分设备确认分别显示结果。旧版沿用原来的手机发起流程。

自动验证覆盖双端增量、重复点击、旧确认与新请求隔离、离线及解除配对。应用明细按所选日期或周的起止时间直接查询，保留跨界时段，覆盖有 500 条以上更新记录的旧日期。待在真实 Windows / Android 上核验同网配对、手机回到前台后的响应、后台省电及变更 IP 后的恢复。

## 浏览器扩展识别

Windows 设置生成专用连接码，Chrome / Edge 扩展取得标签页授权后，仅向本机 40329 端口报告当前普通窗口活动页的域名。采集器还须匹配前台进程。域名改变后切分已有应用时段，同一秒只计一次。失去窗口焦点时清除上下文，停止收到报告后最多保留 45 秒。旧记录的网站列为空。电脑和 Android 通过可空字段保留站点，经现有配对连接交换，并在应用明细中展示。关闭开关撤销连接码，历史明细继续可查。

## 每周报告导出

在每周页标题操作区，从「更新」左侧进入周报。Windows 显示按日叠加的设备用时、应用占比、同期对比和数据覆盖提示。TXT 含文字明细；CSV 按设备、日期和应用导出分钟数；PNG 与单页图像型 PDF 保存预览中的图表。Android 保留文字预览和 TXT 系统文件选择器。导出包含两期起止时刻、时区和日界线、设备累计、主要应用变化与各设备同步状态。网站域名和原始时段不写入周报。取消预览或保存均保留账本原状。

## Windows 0.2.17 行为分类

用户可以从日、周、年查看行为分布。当前周只展示到今天，历史周展示七天。点击周图的一天或年图的一格可进入当天。默认行为为学习、工作、社交、娱乐、运动、生活、出行，用户可以另建行为。没有规则的时段归入未分类。

「全部时段」按开始时间排列，可按全部、手机或电脑筛选。折线图的每个点和柱状图的每根柱子对应一个时段，纵轴表示用时。选中后可改类或撤销，切换图表保留当前时段。超过 32 个时段时可翻组。设备筛选仅作用于下方时段图。行为页只统计原始长度已满一分钟的记录，按日界线拆分前判断长度，原始记录仍保存在账本里。

StayFree 已有跨设备统计和类别限额，在 Windows 实查中也能给应用选类别。这里要验证的是用户愿不愿意按实际用途修正个别时段，并在复盘时查看依据。尚未证实这一组合在 StayFree 所有版本都不存在。[实查记录](STAYFREE-WINDOWS-WALKTHROUGH.md) · [StayFree 功能介绍](https://stayfreeapps.com/)

设计验收：示例周设备累计 56 分钟。“学习”含课程播放器 22 分钟、词典两段 8 和 2 分钟，合计 32 分钟。把最后 2 分钟改为工作后，学习为 30 分钟，工作为 20 分钟，未分类仍为 6 分钟。修改词典默认规则时，已手动修正的时段保持原选择；点“撤销调整”后按最新规则计算。每段只计一次。评审状态仅保存在当前浏览器会话。正式版从真实账本读取记录，按统计时区与日界线切分。应用规则按平台和应用标识保存；单段调整优先，撤销后使用最新规则。行为名称、应用规则和单段调整保存在桌面本地 SQLite，不写入原始计时或向已配对设备发送。[打开行为设计稿](http://127.0.0.1:41875/#desktop-behavior/desktop-v2)

## Windows 0.2.18 桌面图表与应用图标（批注 #120、#121）

桌面图表将时长单位写在纵轴刻度上。行为时段图显示 `20 min`、`10 min`、`0 min` 等刻度，统计页以小时绘图时沿用小时刻度。折线、柱状和设备筛选使用同一单位。周报图像中的小时刻度也应自带单位。

统计页的应用排行在名称左侧显示图标。设计稿的十个示例应用使用独立图标资源。正式版按平台和应用标识查找图标，优先使用能取得的本机软件图标，部分手机应用可复用同款 Windows 软件的图标，其余显示对应平台的通用图标。提取的 PNG 按应用标识缓存在本机 data/app-icons。切换设备或期间后图标跟随应用，排序仍由用时决定。

### Windows 0.2.19 桌面应用排行图标修订（批注 #122）

0.2.18 正式窗口中，ChatGPT 和 Ztime 两行都显示 Windows 通用程序图案。设计稿使用项目沙漏原图、ChatGPT 安装包清单指定的启动图标，以及本机 Chrome、微信、VS Code 的程序图标。每行的 22 px 图标和名称共用一条水平中心线，用时条从名称左缘开始。筛选设备和切换日期后，图标继续跟随应用。

Ztime 使用自带沙漏，Windows 打包应用按可执行文件匹配清单中的启动图标；ChatGPT 还可使用随包保存的同款图标。图标缓存使用新键，以便已经安装 0.2.18 的用户也能直接看到修正。

### Windows 0.2.20 应用排行对齐与图标覆盖（批注 #123）

桌面排行的图标、应用名、横条、设备和时长共用一行，横条有独立的列，长度随用时变化。电脑和手机筛选保持相同的列位置。0.2.21 将名称列固定为 112 px（含图标），列间距 8 px；横条从每行起点后的 120 px 开始。长名称截断显示，悬停可查看全名。设计样例覆盖 Windows 与 Android 应用；手机图标按完整包名在应用商店核对，电脑图标优先核对启动资源。验收同时检查图片内容、同图重复、透明图和占位图。同名的安装程序若无法确定产品，保留身份未知。

待确认的应用按显示名称生成首字母图标，中文名称取拼音首字母。字母图标与品牌图标共用尺寸及对齐方式。

### Windows 0.2.20 统计折线图的选中点（批注 #124）

折线上的数据点画为固定屏幕尺寸的圆点。点击后由 5 px 增至 8 px，在点周围保留较宽的透明点击范围；选中后显示该时段的明细，键盘也可以打开或关闭明细。柱形图保留每个时段对应的柱子。

### Windows 0.2.22 应用排行（批注 #125）

统计页使用已确认画板的排行行样式。名称为 15 px，图标为 22 px，间隔 8 px；设备为 11 px，时长为 13 px。名称列保持 112 px，行之间保留浅色分隔线。评审画板和 Windows 客户端共用排行行渲染、样式及首字母图标。已知程序按对应应用标识展示画板中的名称和图案。正式版仍可点击排行查看真实时段。

### Windows 0.2.23 桌面统计切换与应用图标（批注 #126–128）

应用排行图标使用 18 × 18 px 的固定图标位，与 15 px 名称、横条共用中心线。名称列仍为 112 px，图案与文字间距仍为 8 px。切换日、周、月、年或设备时，选中态立即反馈，上一份统计保留到新结果就绪，图表、排行及累计一次更新。快速连点只展示最后选择的结果，读取失败则恢复已显示的选择并允许重试。

### 桌面设计评审 · 统计工具栏和行为时段图（批注 #129–135）

统计页从左到右依次显示设备、周期、日期和设备累计。设备与周期选择器同高 36 px。日期显示中文月日或日期范围（批注 #136–137）。例如“11月3日”“11月2日到11月3日”，省略星期和“周”前缀，仍可选择日期及查看上一期间。
行为页去掉分布标题旁的累计文字及周分布每行右侧重复的行为说明。行为时段图按日展示小时、按周展示每天、按年展示以周一为起点的周；年首和年末按所选年份截断。坐标轴稀疏标注，详细时间及归类留在所选时间段下方。设备与行为筛选先于分组，选择含多条记录的时间段后仍可切换原始记录、逐条修改及撤销。

## 待决定的开发方向

**行为分类提案。** 使用场景是把桌面课程网页和手机词典一起归入“学习”，周末能说明每段时间为何被计入。建议分两次验收，均需另行确认后进入开发。

1. **先用已有应用记录验证价值。** 用户定义“学习”等行为，将应用与行为关联，查看今日、每周和未分类时长，可对单段作手动修正。建议优先级为手动修正、用户排序的首条匹配规则、未分类。保留原始时段，以独立分类结果支持回算。验收样例：词典 10 分钟中有 2 分钟所在的独立记录被手动改为“工作”，重算后应保留学习 8 分钟、工作 2 分钟，总计仍为 10 分钟。
2. **再验证前台网页细分。** 电脑端扩展需单独授权，仅匹配正在使用的浏览器窗口和标签页。浏览器 30 分钟中若有 20 分钟命中课程页面，课程占 20 分钟，浏览器总量仍为 30 分钟。扩展断开时保留应用记录，历史未采集网址的区间无法回填网页分类。手机端第一阶段只按应用归类。

动工前应确定域名、子域名及路径的匹配方式，哪些最小字段允许保存或同步，双端离线改同一规则如何解决冲突，以及回算如何保留手动修正。验收时应覆盖多规则命中、跨日、断线重试和旧客户端配对。以上均为提案。

**iOS 可行性。** 如果目标是让 iPhone 用户看本机报告，可评估 Apple 的个人授权与报告扩展。如果目标是将 iPhone 使用明细同步进现有 Windows 账本，需另验发行地区、数据授权与返回粒度；汇总时间桶不能直接伪造成应用起止记录。目前项目包含 Windows 与 Android 两个客户端。[Screen Time 对照调研及 Apple 官方依据](SCREEN-TIME.md)
