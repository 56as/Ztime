# StayFree Windows 实测：能看一次会话，不等于能标注这次会话

2026-11-01 · Windows 安装包 3.8.2.0 · 中文界面 · 对照 Ztime 0.2.8

**最值得 Ztime 验证的是按时段复盘用途。** 从 StayFree 仪表板点开一个桌面应用，再点「总会话数 → 详情」，能看到各段时长和起止时间。点击其中一行没有出现编辑操作，弹窗只有「关闭」。回到应用页，「其他设置 → 类别」选择的是整个应用的类别。这是两个不同的操作对象；不能宣传 StayFree 没有分类或没有会话明细。未排除其其他平台、其他入口提供逐段标注的可能。

## 实际走过的路径

- **仪表板 → 应用 → 会话详情。** 仪表板顶部选择日期、统计对象和指标；折线图可见时间粒度与图形选择入口，图例区分桌面、网页、手机和移动网页。下方排行把时长、占比、会话次数放在同一行。进入应用后显示总时长、总会话数、日均及全球日均（无数据也明确显示）；会话明细再深一层。清晰之处是先回答“花在哪里”，再回答“用了几次”；代价是要打开两层才能看到某一段。
- **分类 → ＋。** 默认分类行展示类别和应用/网站数量。加号打开自定义类别名称表单，未填时不能保存。从应用详情展开类别下拉，则可以给这个应用选类别。未创建或更改类别。
- **使用限制 → ＋ → 设置会话限制。** 表单先选择网站、应用或类别，然后选择永久阻止、按计划阻止、每日额度或会话额度。选中会话限制后，其他模式收起，出现可变/固定、冷却期，以及跨设备同步提示。本次可变模式页面显示 5 分钟冷却期。缺少对象时保存不可用。草稿已取消，没有验证拦截效果。
- **番茄钟。** 独立页面以倒计时和「开始专注」为主，当前显示 25 分钟专注、5 分钟休息、4 次会话；下方入口说明可以选要在专注时屏蔽的应用。明确的主操作让用户不必先配置一套规则。未启动计时。
- **设置 → 配对设备。** 页面靠前提供 Google 登录与使用代码配对两条路径，并说明可汇总用量、同步限制。下方还列出每日重置时间、隐藏列表、每日总结通知、避免冲动改设置的密码或文本挑战、备份恢复及退出数据收集入口。未登录、配对或改变隐私选项；仅凭这些入口不能判断数据实际走云端还是局域网。
- **StayFree for Web / 修复问题。** 本机因扩展未连接，仪表板在排行附近提示网站跟踪和限制可能不完整。诊断页把补救拆为安装浏览器扩展，再登录或配对，并提供浏览器入口。对 Ztime 的启发是把“数据为什么少”放在图表附近，而非让用户自行翻设置。
- **收件箱清理器。** 进入后是功能介绍和 Google 登录入口。没有授权邮箱，也没有验证清理效果。它属于产品的外围工具，不是 Ztime 必须补齐的功能。

## 页面设计逻辑

侧栏保持稳定，把观察（仪表板）、干预（限制、番茄钟）和管理（分类、设置、诊断）放在不同页面。页面顶部的日期或指标按钮只改当前视图；新建规则和类别用右下角「＋」；只有选定规则类型才露出专用字段。紫色突出当前导航和主要操作，红色故障入口与常规配置分开。值得借的是这种层级，而不是复制配色。一个取舍：限制列表为空时很简洁，但首次使用必须点「＋」才看到四种模式。

## Ztime 的下一次设计验证

用同一浏览器的两段示例记录测试：第一段查资料 25 分钟，第二段看娱乐内容 15 分钟；再给手机补一段阅读记录。观察用户能否在不改变整个浏览器分类的前提下，给两段指定不同用途，并在周报里核对跨设备学习合计。记录操作次数、是否误改整款应用，以及用户次日是否愿意继续标。这个方向尚未实现。

连接方面应另做对照：两端先配好对，保留局域网、断开外网，分别从 Windows 和 Android 发起同步，检查新记录和失败提示。此次未做双端或抓包测试，不将“只有 Ztime 能离线同步”作为结论。

证据来自本次本机窗口的实际点击，报告未收录真实应用排行、个人使用时间或配对码。[原竞品调研](COMPETITIVE-RESEARCH.md)保留此前官方资料的引用与研究边界。
